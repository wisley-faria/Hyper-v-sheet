📚 Introdução ao Hyper-V Failover Cluster

O que é?

Um Hyper-V Failover Cluster é um grupo de computadores independentes que trabalham juntos para aumentar a disponibilidade de máquinas virtuais e serviços. Se um nó falhar, outro nó assume automaticamente as VMs.

Componentes Principais

  • Nodes: Servidores Hyper-V que formam o cluster
  • Shared Storage: Armazenamento compartilhado (SAN, iSCSI)
  • Network: Rede dedicada para heartbeat e sincronização
  • Failover: Migração automática de VMs entre nós

Requisitos

  • Windows Server 2016 ou superior
  • Hyper-V habilitado em todos os nós
  • Armazenamento compartilhado
  • Conexão de rede dedicada para cluster
  • Mesmo domínio Active Directory
  • Hardware compatível (CPU moderno)

⚙️ Passo a Passo de Configuração

1. Preparar os Servidores


# Instalar Hyper-V (PowerShell Admin)
Install-WindowsFeature -Name Hyper-V -ComputerName Servidor1,Servidor2 -IncludeManagementTools -Restart

# Instalar Failover Clustering
Install-WindowsFeature -Name Failover-Clustering -ComputerName Servidor1,Servidor2 -IncludeManagementTools

2. Configurar Armazenamento Compartilhado

  • Criar LUN no storage (SAN/iSCSI)
  • Conectar ambos os servidores ao storage
  • Inicializar disco no Gerenciador de Disco
  • Formatar como NTFS ou ReFS

3. Criar o Cluster


# Validar cluster
Test-Cluster -Node Servidor1,Servidor2

# Criar cluster
New-Cluster -Name MeuCluster -Node Servidor1,Servidor2 -NoStorage

# Adicionar storage ao cluster
Get-ClusterAvailableResource -Cluster MeuCluster | ?{$_.ResourceType -eq "Physical Disk"} | Add-ClusterResource

4. Configurar Roles de Cluster


# Adicionar função Hyper-V
Add-ClusterServerRole -Cluster MeuCluster -NumRoles 1

# Ou via GUI
# Failover Cluster Manager > Configure Role

⚡ Comandos PowerShell Essenciais

Gerenciamento de Cluster


# Ver informações do cluster
Get-Cluster

# Listar nós do cluster
Get-ClusterNode

# Ver status dos nós
Get-ClusterNode | Select Name,State

# Adicionar nó ao cluster
Add-ClusterNode -Name Servidor3 -Cluster MeuCluster

# Remover nó do cluster
Remove-ClusterNode -Name Servidor3

Gerenciamento de Máquinas Virtuais


# Listar VMs no cluster
Get-ClusterResource -ResourceType "Virtual Machine"

# Mover VM para outro nó
Move-ClusterVirtualMachineRole -Name MinhaVM -Node Servidor2

# Live Migration
Move-VM -Name MinhaVM -DestinationHost Servidor2

# Criar VM de alta disponibilidade
New-VM -Name NovaVM -MemoryStartupBytes 4GB -Path "C:\ClusterStorage\Volume1\NovaVM"
Add-ClusterVirtualMachineRole -VirtualMachineObject (Get-VM -Name NovaVM)

Armazenamento em Cluster


# Listar discos do cluster
Get-ClusterSharedVolume

# Listar recursos de armazenamento
Get-ClusterResource -ResourceType "Physical Disk"

# Ver espaço em disco
Get-Volume

# Adicionar novo disco
Add-ClusterDisk -InputObject (Get-Disk -Number 2)

Rede do Cluster


# Listar redes do cluster
Get-ClusterNetwork

# Configurar rede para cluster e live migration
Set-ClusterNetwork -Name "Rede1" -Role ClusterAndClient

# Listar adaptadores de rede
Get-ClusterNetworkInterface

Monitoring e Diagnóstico


# Ver eventos do cluster
Get-ClusterLog -Destination C:\temp\

# Validar saúde do cluster
Test-Cluster

# Ver métricas de performance
Get-ClusterNode | Get-ClusterResourceHistoryInfo

# Check heartbeat status
(Get-ClusterNode).NodeHighestVersion

🔧 Troubleshooting Comum

❌ Cluster não forma

Causa: Diferenças de versão, conectividade de rede, firewall


# Verificar versão do Windows
Get-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' | Select CurrentVersion

# Testar conectividade
Test-NetConnection -ComputerName Servidor2 -Port 5985

# Verificar firewall
Get-NetFirewallRule -DisplayName "*Cluster*" | Select Name,Enabled

❌ VM não faz failover

Causa: Storage não acessível, VM não configurada como HA


# Verificar se VM está em resourse group
Get-ClusterGroup

# Testar acesso ao storage de ambos nós
Get-ClusterSharedVolume | Select Name,State

# Verificar espaço em disco
Get-Volume

❌ Nó desconectado do cluster

Causa: Problema de rede, heartbeat falha


# Ver status do nó
Get-ClusterNode -Name Servidor2 | Select State

# Forçar sincronização
(Get-ClusterNode -Name Servidor2).NodeHighestVersion

# Reiniciar serviço de cluster
Restart-Service -Name ClusterSvc -ComputerName Servidor2

⚠️ Dicas Importantes

  • Sempre use Live Migration em vez de reinicializar nós
  • Configure VM Monitoring para restart automático
  • Mantenha quorum adequado (maioria dos nós online)
  • Use Cluster Shared Volumes (CSV) para melhor performance
  • Teste failover regularmente
  • Mantenha logs de cluster para diagnóstico
